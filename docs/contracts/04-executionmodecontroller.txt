B6) Hard Guarantees
Replay semantic identity (LOCKED):
• For V1, replay is semantically identical to backtest execution.
• Any reference to “replay” MUST be interpreted as backtest execution operating on a finite adapter-provided historical candle stream, with no special-case replay behavior.

Finite vs indefinite classification (LOCKED):
• backtest/replay are finite modes (is_finite = true; eof_expected = true).
• demo/live are indefinite modes (is_finite = false; eof_expected = false).

EOF definition boundary (LOCKED; from V1 Gap Handling Policy):
• EOF occurs when the active adapter explicitly signals completion of a finite stream (backtest/replay/CSV replay).
• Live/Demo does not define EOF; loss of candles in live/demo is handled as a missing-candle condition.

Clean-start assumption (LOCKED; from V1 Gap Handling Policy):
• On process start, the engine initializes into a clean execution state and does not attempt to detect, resume, reconcile, or manage trades opened prior to this process start.

Pass-through boundary guarantee (LOCKED interface):
• evaluation_start_timestamp and evaluation_end_timestamp are pass-through fields in ExecutionModeContext and MUST be returned unchanged if supplied in ExecutionModeInput.



B7) Hard Prohibitions
This module MUST NOT:
• read logs as inputs (directly or indirectly)
• query wall-clock/system time or data sources
• fabricate, interpolate, bridge, or infer missing candles, timestamps, or boundaries
• reinterpret, normalize, parse, or timezone-shift evaluation_start_timestamp / evaluation_end_timestamp (pass-through only)
• synthesize EOF or convert indefinite modes into finite semantics
• implement phase logic, pointer advancement, scan suspension/resume rules, trade state, entry/exit decisions, or outcome simulation
• mutate unrelated execution state or special-case other modules
• introduce defaults or “best guesses” for any behaviour that is UNDEFINED IN AUTHORITY



B8) Swappability Rules (Swappable)

Replaceable implementation:

B9) Failure Modes
Fatal (halt run; mark run INVALID):
• ExecutionModeController cannot be constructed or invoked at orchestration Step 4.
• ExecutionModeInput.execution_mode is missing or not one of {backtest, replay, demo, live}.
• Backtest / Replay startup empty-stream rule (LOCKED):
  – If, after applying execution-start gating, the engine receives zero adapter-provided fully closed candles in evaluation scope, the run MUST hard-fail and be marked INVALID.
• ExecutionModeController fails to return a valid ExecutionModeContext containing all required fields.
• Any downstream component attempts to treat demo/live as finite or to synthesize/assume EOF in demo/live.

UNDEFINED IN AUTHORITY → HARD FAIL IF REACHED (no defaults):
• Failure-outcome handling for the case where an adapter incorrectly emits an explicit EOFEvent in demo/live is not explicitly defined as a mandatory deterministic outcome in authoritative text; therefore, if this condition is encountered at runtime and requires a deterministic resolution decision, the run MUST hard-fail rather than invent a response.

UNDEFINED IN AUTHORITY → HARD FAIL IF REACHED (no defaults):
• Any deterministic criteria for deciding when to “hard-stop the bot process if safety requires” (live/demo violation handling language) are not explicitly defined as deterministic rules; therefore, this module MUST NOT implement discretionary safety criteria, and any attempt to require deterministic “safety requires” decision logic MUST hard-fail rather than invent it.
