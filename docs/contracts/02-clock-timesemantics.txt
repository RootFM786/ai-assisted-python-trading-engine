B6) Hard Guarantees
UTC-only guarantee:
• The canonical timestamp type for V1 is timezone-aware UTC datetime.
• utc_assert enforces this contract: any non-UTC-aware timestamp MUST hard-fail the run at the moment the violation is detected.
• UTC localization occurs once, immediately upon adapter ingestion.
• No timestamp may be altered, shifted, rounded, or re-parsed after localization.
• All timestamp comparisons (<, >, ==, in) assume UTC-aware datetime objects.

Candle open→close derivation guarantee (mechanical, deterministic):
• The adapter-provided candle timestamp is the candle OPEN time (UTC).
• All “candle close” logic in Phase 1–3 uses derived close time:
  – M5 close = open_time + 5 minutes
  – H1 close = open_time + 1 hour
• The raw open timestamp MUST NEVER be treated as a candle close timestamp.

Canonical “NOW” guarantee (pointer execution):
• now_utc is the canonical engine-wide “current time” value.
• now_utc equals the derived M5 candle close timestamp (UTC) of the current pointer candle being evaluated.

Comparison basis guarantee (engine-wide timing language):
• Any rule that references “now”, “current time”, “at candle close”, “entry time”, “confirmation_time”, or equivalent timing language during pointer execution MUST use derived candle close timestamps and/or now_utc (as defined above), not wall-clock time or raw candle open timestamps.

Timestamp serialization (engine-wide; mandatory sinks):
• All timestamps written to mandatory sink CSVs MUST be serialized as UTC ISO-8601 with “Z” suffix (YYYY-MM-DDTHH:MM:SSZ).
• No fractional seconds are permitted.

Single-context guarantee:
• TimeSemantics initialization produces exactly one immutable TimeSemanticsContext object for the run.



B7) Hard Prohibitions
This module/context MUST NOT:
• read logs as inputs (directly or indirectly)
• query wall-clock/system time to define “now/current time” for pointer execution (only now_utc as defined is permitted)
• perform timezone conversion beyond the UTC-only contract (no shifting between timezones)
• alter, shift, round, or re-parse adapter-provided open timestamps after UTC localization (it may only assert UTC-awareness and derive close timestamps mechanically)
• treat raw candle open timestamps as candle close timestamps
• fabricate, interpolate, bridge, or infer missing timestamps or candles
• construct or allow the existence of multiple competing time-basis objects for a single run
• embed strategy logic, phase logic, pointer advancement, trade decisions, or outcome logic



B8) Swappability Rules
Not applicable (not a swappable slot in V1).



B9) Failure Modes
Fatal (halt run; mark run INVALID):
• TimeSemanticsContext cannot be constructed at orchestration Step 2.
• utc_assert is invoked on any timestamp that is not timezone-aware UTC.
• derive_close_timestamp is invoked with:
  – a timeframe outside {M5, H1}, or
  – an open_timestamp_utc that is not timezone-aware UTC.
• Any module attempts to define “now/current time” for pointer execution using wall-clock/system time instead of now_utc.
• Any competing or divergent “time semantics” object is constructed independently by downstream modules for the same run (if detected).
